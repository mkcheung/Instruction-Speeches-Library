## 1. Intended interaction and scope

Add an accessible draggable playhead to both existing commentary timelines: the speech owner's under-video **Commentary timeline** and the reviewer's annotation workspace. The feature is navigation through the speech, not annotation editing.

- Keep the Text ranges, Voice points, their exact positions, marker click behavior and existing video controls.
- Add a small grip in a dedicated **44px-high scrub row above the annotation lanes**, aligned with the same data/time axis. This prevents the grip's touch target from covering annotation buttons. The existing thin playhead continues through the lanes.
- During a pointer drag, move the grip/playhead to a local candidate and show a time preview, clearly labeled **Release to seek**. **The actual video changes position once, on release.** Continuous frame-by-frame seeking during dragging is intentionally not part of this first implementation.
- Keyboard interaction seeks immediately: Left/Down and Right/Up by one second, PageDown/PageUp by ten seconds, Home to zero, End to the native duration. Clamp every target to the valid duration.
- Preserve the video's current playing/paused state through the existing seek path. Do not call play, pause, skip commentary or resume commentary from this control. An already playing video or voice can continue during the local preview; committing the seek follows existing native cancellation behavior. Cancelling a drag has no media effect.
- Do not change annotation timestamps, endpoints, recording positions, draft values, selected-note state, pagination, publication, commentary mode/reviewer selection, poster frames, or seen/read state.
- Owner scrubbing remains available with commentary Off, an empty track or no reviewer selected, provided the speech's own playback binding is valid. Marker visibility and marker navigation continue following their existing mode/access gates. The scrubber does not expose commentary data.
- Reviewer scrubbing is enabled only for a valid current media/review binding while Notes is active and the microphone is neither being requested nor recording. Navigation does not require annotation write permission by itself. Preserve existing recording locks, drafts, portal and marker/reveal behavior.

This is a frontend change. No backend endpoint, schema, Redis/Valkey work, object-storage operation, media processing, new package or durable preference is needed. Reviewer entry does require a bounded validation GET through the **existing** `/api/reviews` endpoint, as detailed below; owner scrubbing adds no fetch. There is no new polling loop or annotations request.

## 3. Component and integration contracts

### Shared opt-in control

Create `web/src/components/annotation/TimelineScrubber.tsx` and its focused test file. Keep pointer/keyboard/media-listener cleanup isolated there. It is a navigation-only component, not a second media controller.

Extend `TimelineStrip` with one optional structured scrub capability containing:

- A current binding identity including user, speech, asset, relevant review and rendered source generation.
- An explicit enabled flag and visible/active flag from the caller.
- A scrub-specific, current-source-guarded seek callback.

Use the existing `videoEl` for media binding. Default capability is absent, preserving all existing standalone timeline call sites and their three-row layout. An opted-in but temporarily unavailable control can remain visible and disabled. Do not key the whole TimelineStrip, utility, Frame selector or player by scrub state or source generation merely to clear a gesture.

When opted in, reserve the extra row in the existing grid, shifting Text/Voice/ticks down without changing their time-axis width or interval geometry. Extend the existing axis overlay to cover the extra row. Place the scrubber **inside that axis's first row** so it inherits the existing `--playhead-percent`; its own 44px row alone gets pointer events. The overlay elsewhere remains pointer-events-none. This avoids moving the rAF writer or changing the existing axis-ref contract just to share position with a sibling.

Use a custom horizontal `role=slider` with a visible grip and local time readout. It needs an accessible name **Video position**, `aria-valuemin=0`, finite native `aria-valuemax`, current seconds, and a spoken current/total `aria-valuetext`. Use existing time-format helpers. Disabled controls are explicitly unavailable and cannot receive keyboard/pointer navigation. Avoid an aria-live announcement for every pointer movement or playback tick.

Playback position continues to use the existing CSS property. For accessibility/readout, the scrubber may attach narrow native timeupdate/seeking/seeked/metadata listeners that write its own DOM attributes/readout imperatively when not dragging. They must not set playback-tick React state, calculate annotation cues, request audio, or run another rAF. Cleanup follows the exact bound element. Resynchronize from the current video after commit/cancel/source changes and after unrelated React commits, so a rerender cannot overwrite current imperative ARIA/readout values with an old initial value. Native finite duration is required for interaction; asset duration remains a display/layout fallback only.

During a gesture, maintain a local preview ref/value and `--scrub-preview-percent` on the existing axis; the line and grip prefer that property when it exists, otherwise the normal rAF value. Do not overwrite `--playhead-percent` on pointermove or freeze its actual-time updates. Clear the preview property on completion/cancel/unmount; the existing writer again displays actual time. Ensure any React state is interaction/lifecycle state, not a re-render on every media tick.

### Owner caller

`SpeechWatch` passes the current scrub binding identity alongside its existing owner scope/readiness. Source generation belongs in the scrub identity, **not** the utility's scope key: same-asset source refresh must preserve Frame selector and utility tab state.

`OwnerVideoTools` opts in with its current bound video, playbackReady, `tab === 'timeline'`, binding identity and a scrub-specific guarded callback. Its existing marker wrapper and seekOwnerTimeline behavior remain unchanged. The new scrub callback additionally compares the captured binding with the latest committed route/auth/source state before using the same canonical commentary seek. Scrub dispatch bypasses that marker-only wrapper but never bypasses playback/auth/source readiness. It must work with valid video plus Off/no-selection/empty/unavailable commentary, with no additional annotation fetch or privacy change.

### Reviewer caller

`SpeechWatch` provides a separate reviewer scrub binding only when the current route/source/player/video and **validated current-user review scope** agree. Bare previewIdentity is insufficient. The guarded callback checks latest committed auth/review validation, source generation, concrete video/player and disposal before invoking the existing local seek helper. Keep the existing general authoring `videoEl`, marker callback, previewIdentity and timing/preview contracts unchanged.

Pass this narrow capability into `AnnotationComposerPanel`. Combine its enabled state with `authoringActive && !recorderLocked`; preserve source identity even if the current audio/text tool changes. No `writable` requirement is added solely for seeking. A local control disabled during microphone request/recording does not attempt to stop the recorder, change its anchor, or discard a recording.

#### Reviewer validation without changing the existing review hook

- Observe the existing `reviewApi.endpoints.listMyReviews` query state in `SpeechWatch` with its installed `useQueryState` or equivalent store selector, without an additional subscription. Keep useMyReviewForSpeech and the current endpoint contract unchanged. There is no reliable reviewer.id in this response to compare with getMe.
- Scope authorization to the current authenticated-user epoch and speech/review identity. Reject terminal **401/403/404/410** on current getMe, speech or review query even when RTK retains old data. Unresolved/replaced auth cannot borrow an old account's validation.
- On entry to an unvalidated reviewer context, allow one bounded validation GET of the existing endpoint, with no subscription or polling. A request must be **known to have actually started for this epoch**. RTK `forceRefetch` can deduplicate against an older in-flight void-key request, so resolving an initiate/unwrap promise is not evidence of a fresh request.
- If an older request is pending, await its settlement without aborting other subscribers; recheck current context, then initiate fresh validation. Record the actual new pending requestId and epoch. Accept only its matching fulfilled result while the auth/speech/review context remains current and the returned sections contain the current access-granting, non-revoked review for this speech. A stale review candidate from a previous account cannot validate itself merely by remaining in data. A response whose fresh review identity differs must first reconcile the current review; do not commit a gesture under the obsolete identity.
- Synchronize the validation result/current gates before a gesture can commit. An account change, route/review change or terminal denial invalidates validation and pending gesture immediately. An old request's late success cannot validate the new epoch. A later network/500 failure cannot revive a terminally invalidated scope; a genuinely fresh matching validation success is required. Same-source generation/native epoch changes cancel gestures but do **not** themselves trigger another review-validation GET.
- Same-context nonterminal background refresh failure may retain an already validated scope, subject to exact media/source guards. An initial validation failure stays unavailable; do not retry in an effect on every error/render. Expose a small **Retry timeline navigation** action in the existing reviewer workspace notice, only when current auth/speech permits it, to run one new bounded verification attempt. Route re-entry or a later current-epoch request known to have actually started can also provide fresh proof. Disable duplicate retry while one attempt is pending.
- Request lifetime guards prevent starting a queued verification after its scope disappears. Do not abort a shared older query or reset shared review/auth caches to implement this feature. This validation is only for the new navigation capability; it does not broaden or refactor existing authoring/preview permissions.

The extra read request is a deliberate consequence of the existing user-agnostic review cache and omitted reviewer identity. If this request provenance cannot be implemented/tested within the route inventory, stop and report rather than silently accepting stale data or editing shared auth/query code.

## 4. Pointer, keyboard and lifecycle behavior

### Pointer session

1. Accept one primary left-button mouse, pen or touch pointer on the scrub row/handle. Ignore secondary buttons and extra pointers. Validate enabled/visible/current binding, finite positive native duration, no media error and at least HAVE_METADATA before starting. Require a nonzero finite measured axis width.
2. Capture that pointer on a stable control element. Keep the actual element, binding identity, native-source epoch, duration, pointer ID, pointerdown coordinates, grip-versus-rail origin and horizontal-movement flag in the gesture record. Capture failure aborts the gesture safely.
3. Calculate candidate seconds from `clamp((clientX - axis.left) / axis.width, 0, 1) * nativeDuration`. A grip-origin drag accounts for grab offset so a slightly off-center grab does not jump. A click/tap elsewhere in the dedicated scrub row previews that position and commits on release. Never attach seek pointer handlers to the annotation lanes or overall card.
4. Pointer moves update preview/time text only. Use current measured geometry and cancel if a resize/reflow invalidates the starting geometry. Do not use pageX, a cached whole-card width or a voice-collision estimate. Preserve normal vertical touch scrolling with a narrow touch-action policy on the scrub row; browser pan cancellation must produce no seek. Keep pinch zoom available.
5. On matching pointerup, validate the whole session again, use the final pointer position, and clamp against the same still-valid native duration. A grip-origin gesture commits only after at least **3 CSS pixels of horizontal movement from pointerdown**, considering both pointermove and the final pointerup coordinate. A stationary grip hold never seeks, even if actual playback advanced while held; do not infer user intent by comparing the old preview to the now-advanced video time. Rail clicks can commit without movement. After validation, clear the active session **before** releasing capture, then make at most one guarded seek. Skip a genuinely unchanged target. Moving away and back is an intentional drag; the explicit movement flag distinguishes it from a stationary hold.
6. Pointercancel, premature lostpointercapture, Escape, blur, document hiding, disabled/inactive transition, missing media, source/binding change, changed duration, or unmount cancels with no seek. Repeated terminal events must be idempotent. Late events from the old pointer/video cannot change a new session.

At start and commit, inspect the actual control as well as props: it must still be connected, have nonzero finite layout, be visibly rendered and have no hidden/inert ancestor. Base UI makes a kept-mounted panel inert immediately on closing, before its separate hidden state finishes transitioning; capture is not permission to interact through that ancestor. Add a regression that makes only an ancestor hidden/inert without rerendering the scrubber and then delivers the captured pointerup: it must not seek. Do not confuse a captured pointer legitimately outside the control with a hidden control; outside releases still clamp when the control itself is valid.

Read the latest enabled/binding/callback state at commit rather than trusting a pointerdown closure. The route callback must independently compare against the **latest committed** auth/review/source/player/video binding, not only captured booleans such as ownerPlaybackReady. Synchronize live gates before an event can commit, using commit-synchronous refs/layout effects rather than a passive-effect-only update; never publish an abandoned concurrent render as the current binding. Revalidate the captured session identity against that committed binding before dispatch. Keep cancellation and event cleanup safe under React StrictMode and unexpected capture loss.

### Keyboard ownership

- Focus the scrubber on pointer interaction and make it reachable by Tab when enabled. Show a visible focus indicator.
- Apply the steps in section 1 using the actual native currentTime, or the current candidate when resolving a keyboard action during a pointer preview; clamp before dispatch. Keyboard seeks use the same guarded callback. End means the actual finite duration, not duration minus an arbitrary epsilon; normal native ended behavior applies.
- A keyboard seek during a pointer preview ends that preview first and prevents the subsequent pointerup from seeking again.
- Escape while previewing cancels, preventDefault and stops propagation, so the voice controller cannot process the same key as Skip.
- Keep focused-slider app shortcuts local: Space/Enter must not toggle the video, C must not stamp a note, and J/L/brackets/comma/period must not also seek through a global shortcut. Preserve modifier-based browser defaults while preventing the same keydown reaching app handlers: stopPropagation does not require preventDefault for Ctrl/Meta browser chords. Leave ordinary wheel scrolling native. Tab/Shift+Tab move focus normally and cancel a pending preview without committing it.
- Keyboard behavior must remain local; no change to `useKeyboardShortcuts` or `VoiceInterjectionController` is proposed.

### Native source epoch and media state

Listen for loadstart, emptied and error to invalidate the local media epoch, cancel any preview and disable until the current source again has valid metadata/duration and caller readiness. Keep an explicit **metadata observed for this epoch** condition: a retained finite duration or durationchange alone cannot clear invalidation after a source reset/error. At first attachment to an already ready element, initialize from its actual current metadata/readiness. Thereafter require a valid loadedmetadata event for the new epoch before enabling it again. Handle durationchange safely; a changed/invalid duration cancels, rather than rescaling a pending release into a different timestamp. Read the current source/readyState/error/duration at commit, as well as the epoch and route binding; metadata listeners or old player callbacks cannot restore a retired element.

Cancel on React binding identity/video replacement too. A kept-mounted hidden timeline must cancel immediately and stay nonfocusable. A signed-URL refresh on the same element must cancel through native lifecycle events even if no React identity changes. Switching commentary reviewer/mode alone need not interrupt a valid speech-position preview for the owner; it changes markers, not the media binding. Reviewer review identity changes do cancel.

No automatic pause at drag start or play at completion is introduced. Existing actual video/voice playback can naturally progress during a preview; a cancellation restores the indicator to **current actual time**, not its old pointerdown time. On commit, native seeking/seeked cancels voice through the current controller. Do not manually dispatch those events in production, call skip, or add a second cancellation path. Delayed voice URLs must retain their existing generation rejection.
